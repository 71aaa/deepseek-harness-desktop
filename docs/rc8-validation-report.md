## Runtime generation result

The rc8 root package pins `@deepseek-ai/dsh` to `0.1.0-rc.8` and explicitly adds `@deepseek-ai/cordis-plugin-group@1.0.1`. Standard npm peer resolution also installs `@deepseek-ai/dsh-scope@0.1.0-rc.8`.

An initial install using `--legacy-peer-deps` produced a launcher that could print help but failed to boot the Web profile because peer packages were absent. The complete test runtime was regenerated by running standard npm peer resolution; the lockfile in `runtime-spec/rc8` is the validated input. Do not generate production runtime with `--legacy-peer-deps`.

## Known risks

- rc8 depends on peer packages that are not complete under `--legacy-peer-deps`; always use the validated lockfile and `npm ci` for reproduction.
- npm reported five pending install scripts. The validation passed without approving them, but production packaging must record the script-approval policy and validate native-dependent features on a clean target machine.
- The Desktop lifetime state and logs remain fixed by C# under `%LOCALAPPDATA%\\DeepSeekHarnessDesktop`; only Harness user data was isolated via `DSH_HOME`.
- rc8 remains a pre-release runtime. Profile plugins and an existing user `~/.dsh` copy still require a separate compatibility test before production release.

## v1.1.0 rc8 upgrade file plan

Required release-input changes:

- `runtime-spec/rc8/package.json` and `runtime-spec/rc8/package-lock.json`: validated runtime definition.
- `runtime-manifest-rc8.json`: release provenance, lockfile hash, and peer-dependency record.
- `dsh-runtime/package.json`, `dsh-runtime/package-lock.json`, and its regenerated `node_modules` at release-build time: replace rc6 only after the rc8 change is approved. These are not changed in this preparation commit.
- `publish/dsh-runtime/**`: regenerated release output only; never edit the formal rc6 publish output in place.

Documentation changes for the release:

- Update `README.md` to state the bundled validated Harness version and reproducible runtime policy.
- Preserve `runtime-manifest.json` as the rc6 baseline and ship `runtime-manifest-rc8.json` with v1.1.0 records.

No C# changes are required by the completed isolation test:

- `HarnessService.cs` remains unchanged.
- `AppConfig.cs`, port detection, PID/ownership validation, and WebView2 loading remain unchanged.
